# Bread Line (job radar)

A daily remote job finder: it pulls postings from company job boards and aggregators, filters them, then hands the new matches to your coding agent (Claude Code or Codex) to score against your resume and load into the Bread Line tracker page. Plain Node 20+, with no dependencies.

The engine (`src/`, `scripts/`, `tracker/`) is shared. Everything about one person lives in their profile folder, so the same engine can run for anyone.

## Profiles

```
profiles/
  active.txt                  name of the profile the scripts use by default
  _template/                  the blank profile new ones are copied from
  <name>/
    profile.json              tracker URL, resume fallback, salary floor, boards to pull, LinkedIn settings
    filters.js                role categories, off-limits topics, seniority and title exclusions, digest signals
    scoring.md                the rubric Claude scores against
    companies.candidates.json the watchlist
    companies.json            boards found for the watchlist (generated by `npm run discover`)
    data/                     seen list, runs, scores and tracker batches
```

To run a different profile once, add `--profile <name>` (`npm run radar -- --profile sam`) or set `BREADLINE_PROFILE=<name>`. To switch for good, change `profiles/active.txt`.

**Adding a person.** Open Claude Code or Codex in this folder and say "set up Bread Line for me". The `bread-line-setup` skill (`.claude/skills/` for Claude, `.agents/skills/` for Codex) reads their resume, asks what they want, writes their profile, finds their companies' job boards, tunes the filters with dry runs, sets up their own tracker page (a private claude.ai page with Claude, an offline file with Codex), and schedules their weekday run. The pieces it uses:

```
npm run profile:new -- sam                  # copy profiles/_template to profiles/sam
npm run profile:check -- --profile sam      # list anything unfinished; prints "Ready." when done
```

Profiles hold resumes and job history, so `.gitignore` keeps everything in `profiles/` except `_template` out of git.

**Sharing the kit.** `npm run kit` packs the shared parts (never a profile other than `_template`) into `site/bread-line.zip` and `site/bread-line-kit.json`, which the landing page in `site/index.html` offers for download. Run it after changing the engine, then republish the landing page.

`filters.js` overrides the engine defaults in `src/config.js`: any export with the same name wins. The defaults have no role categories and nothing off-limits, and they keep remote roles that are open to the US.

## Run it

```
npm run radar       # fetch, filter, write the profile's data/new-jobs.json
npm run radar:dry   # same, but doesn't update the seen list (safe to re-run)
npm run show        # print new-jobs.json as a table
npm run discover    # find job boards for new companies in the watchlist
```

The scheduled task `job-radar-daily` runs weekdays at about 8 AM, while the Claude app is open. If the app is closed at that time, it runs on the next launch. You can start it any time with "Run now" in the app's Scheduled section, or follow `RUNBOOK.md` by hand. Jobs are marked as seen only after they reach the tracker (`npm run radar:commit`), so a failed or repeated run never loses or duplicates jobs.

## Tracker page

Each profile has its own copy of the tracker page. With Claude it's a private claude.ai page, whose URL is `trackerUrl` in `profile.json`. With Codex or any agent that can't publish pages, set `"tracker": "local"`: `npm run tracker:local` then builds `bread-line.html` in the profile, an offline copy that keeps status and notes in the browser. The source is `tracker/index.html`. Jobs live in the page's database (`jobs/<id>`, plus a `meta/latestRun` digest), so status changes and notes are kept across republishes.

To load a run: `npm run tracker:prep` writes `data/tracker/batches.json` in the profile, and Claude sends each batch to the page's database (at most 50 writes per batch). Each job is created once with status `new`. Later scoring only merges `score`, `reason`, `gaps` and `headline` into existing jobs, so status and notes are never overwritten.

**Resume and cover letters.** Use the page's Resume button to upload a PDF, .docx or text file, or paste the text. The text is read in the browser and saved to `profile/resume`. Each job's details have a "Write cover letter" button. It sends the resume, the posting text (`description`) and the fit notes to Claude on the viewer's own account, then streams the letter into an editable box. Letters save to the job as `coverLetter` and can be copied or downloaded as .txt. The daily scoring reads the same uploaded resume.

## Scoring

The rules are in the profile's `scoring.md`. `npm run digest` condenses the new jobs into `data/digest.txt`. Claude scores them and saves the results with `node scripts/save-scores.js <pass.json>`, which writes to `data/scores.json`. After that, `npm run tracker:prep` includes the scores and the top 3 in the documents it loads. For jobs that are already in the tracker, `node scripts/scores-to-tracker.js <version>` builds update-only batches instead.

## Data files (in the profile's `data/`)

- `new-jobs.json`: the latest run's new matches, for scoring.
- `runs/YYYY-MM-DD.json`: each run's summary, including why jobs were dropped.
- `seen.json`: every job ID already processed.
- `linkedin-inbox.json`: jobs read from LinkedIn alert emails, waiting for the next fetch.

## Sources

Greenhouse, Lever and Ashby boards for the watchlist, plus whichever of these the profile's `boards` lists: Remotive, Remote OK, CryptoJobsList, the monthly HN "Who's Hiring" thread, and LinkedIn alert emails. web3.career is not included because its API needs a paid token. Indeed is not included either; add those jobs by hand in the tracker.
